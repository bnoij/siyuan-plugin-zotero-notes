# Zotero 参考插件能力整合设计

## 背景与目的

当前插件已提供 Zotero 10+ 文库树、论文页/Note、回传、缓存、迁移和自动化导入。用户希望分阶段吸收 `reference/` 中三个 Zotero 插件的能力，但必须适配现有技术栈，而不是完整迁移或拼接 bundle。

参考来源：

- `reference/siyuan-plugin-zotero-cite/`：CSL 正文引用、文末表、编辑、快照、撤销、多页管理和临时集合。
- `reference/siyuan-plugin-citation/`：模板化文献库、块引用、PDF 标注、数据库映射、Word/LaTeX/Markdown 导出、多数据源。
- `reference/siyuan-paper-manager/`：Connector 接收、PDF 识别、原生数据库、pdf2zh 翻译、静态引用导出。

## 目标

- 保持一个插件、一个独立 Git 仓库和统一设置/文库状态。
- 最终覆盖适合当前插件的引用、写作、标注、导入、数据库、导出与翻译工作流。
- 优先复用当前 Zotero Local API、思源内核 API、Lute 和 Pandoc 能力。
- 每阶段都有独立可验证的用户功能、回归测试和可回滚 Release。
- 保持现有生命周期修复，不因新增功能恢复启动写入或跨窗口重载循环。

## 非目标与限制

- 不拼接三个参考插件的打包产物，不复制其完整 UI 或全局状态。
- 不为了“功能名称一致”引入不必要的外部插件、远程服务或隐藏依赖。
- 不支持 Zotero 7、群组文库和移动端；首阶段继续保持桌面端。
- 不自动开启与 Zotero 桌面端冲突的 Connector 服务。
- 不在未获得授权时修改 Zotero 条目、分类或文献库。
- 不直接复制无许可证或带非商用限制的源代码。

## 技术路线与已选方案

用户选择“分阶段整合全部功能，同时批判性引进并适配现有技术栈”。

### 统一基础层

- Zotero 读取、写入和版本校验继续使用 Local API。
- 思源文档、块、属性、数据库和文件操作继续使用内核 API。
- Markdown/HTML 转换继续使用 Lute；文档转换优先考虑内置 Pandoc。
- 保持免构建 CommonJS 插件产物，不把 Node/npm 作为用户运行依赖。
- 新功能按职责拆分为插件内模块或清晰的独立类，共用文库客户端、绑定、设置、锁和错误模型。
- 所有定时任务、事件和异步任务纳入生命周期管理；`onDataChanged` 只更新状态，不写文件。

### 替代外部桥接的原则

- 能通过 Local API 获取的条目、附件、笔记、标注、集合、版本和参考文献结果，不使用 ZBridge。
- 对数字式、作者-年份式引用，优先基于标准 CSL-JSON 元数据和 Local API 的格式化结果实现。
- 任意自定义 CSL 的精确排版若 Local API 无法完成，应先验证 Local API 的样式/格式化能力；确实不能替代时，将高级能力单独标记为受限，不引入默认桥接依赖。
- Zotero 临时集合、标签和反向链接可通过 Local API 写入实现，不需要 debug-bridge。
- Connector 接收改为复用 Zotero 已保存条目的增量导入；只有用户明确需要且自行配置独立端口时，才考虑可选接收服务。
- PDF 翻译直接调用用户已有或明确授权安装的 pdf2zh CLI，不迁移参考插件的环境管理代码。

## 分阶段实施

### 阶段 1：引用、标注与写作导出

目标：让用户能从当前 Dock/编辑器插入文献引用、导入 Zotero 标注，并导出写作结果。

- 统一文献搜索选择器，支持多选、Zotero 当前条目定位、静态/动态锚文本。
- 支持数字式和作者-年份式正文引用；维护文档内引用顺序和文末参考文献。
- 引用链接包含稳定 itemKey，引用编辑/刷新不修改无关正文。
- 参考文献优先使用 Local API 的格式化能力；不支持的高级 CSL 行为明确提示。
- 导入 PDF 高亮、批注、页码和 Zotero 跳转链接到论文页或 Note。
- 提供 GB/T 7714、APA、IEEE、BibTeX/BibLaTeX、Typst 和 LaTeX 常用导出。
- 使用思源/Pandoc 能力导出 Markdown、Word 和 LaTeX，保留引用映射。
- 提供文档撤销或明确的可恢复写入策略。
- 验证多页文档时不吞掉文献表后的用户内容。

验收：数字式与作者-年份式插入/刷新、文末表、标注导入、各格式导出和双窗口操作均有自动化与真实环境验证。

### 阶段 2：模板、数据库与导入增强

- 提供安全的论文页/Note 模板变量；不执行模板中的任意 JavaScript。
- 保留用户数据区域，刷新元数据不覆盖 Note。
- 支持思源原生数据库字段映射和文献行绑定。
- 支持 BibTeX/CSL-JSON 文件导入，统一转换为当前文献模型。
- 支持 DOI、arXiv、ISBN、PMID/PMCID、URL 等标识符检索。
- 研究本地 PDF 文本提取；能复用思源/Zotero 已有能力时不引入额外 PDF 引擎。
- 对 DOI/标题相似度查重，合并或新建必须由用户确认。
- 文献库维护操作默认不删除整棵子树；危险操作单独确认。

验收：模板特殊字符、空字段、重复文献、数据库同步、文件导入和失败恢复均有覆盖。

### 阶段 3：翻译与高级工作流

- 调用 pdf2zh 生成单语/双语 PDF，保留原稿关联、进度、取消和错误状态。
- 批量任务串行/受控并发，卸载时停止调度，不遗留无界任务。
- 密钥只读取思源密钥和变量，不写入配置或日志。
- 评估多页统一引用编号、自动 Reference 子文档和 Zotero 临时集合。
- 提供稳定的 eventBus/Agent Action 接口供其他工作流复用。
- 高级自定义 CSL、复杂 PDF 识别或外部部署若未经验证，不作为默认承诺。

验收：翻译失败、取消、重启、并发、密钥和外部命令错误均安全处理；高级功能有独立测试。

## 许可证与复用边界

- 当前项目保持 AGPL-3.0。
- MIT 代码复用时保留版权与许可证。
- `siyuan-plugin-citation` 未提供许可证，只借鉴公开数据协议和交互思路，代码独立实现。
- `siyuan-paper-manager` 的 PolyForm Noncommercial 代码不直接复制；公开协议、pdf2zh CLI 和数据格式可独立实现。
- 字体、PDF.js、WASM 等第三方资源不因参考插件包含就直接搬运；确有需要时逐项检查许可证并列入包校验。

## 测试与发布

- 使用 Node 内置测试，新增纯函数和接口测试；每个缺陷先写失败测试。
- 保留现有生命周期、缓存、锁、绑定和转换测试。
- 新增引用编辑、文末表边界、标注转换、模板注入、数据库映射、查重、外部命令失败等测试。
- 每阶段更新版本、README、测试和 `package.zip`，ZIP 使用 `/` 路径且不包含开发测试文件。
- 每阶段在真实 SiYuan + Zotero 10+ 环境验证；多窗口场景为必测项。
- 未实际验证的外部能力不得标为已完成。

## 可实施性核查后的具体决定

### Local API 排版能力（已实测）

真实 Zotero 10.0.7 已验证：

- `format=bib&style=ieee` 能返回带编号的 IEEE 参考文献 HTML。
- `format=bib&style=apa` 能返回 APA 参考文献 HTML。
- `format=csljson` 能返回标准 CSL-JSON 元数据。

因此阶段 1 不需要引入 citeproc 或 ZBridge：参考文献使用 Local API 的 CSL 格式化结果，常见数字式/作者-年份式正文引用由插件基于 CSL-JSON 生成。任意 CSL 的复杂正文规则不承诺完全复刻。

### 当前选中项

Local API 没有读取 Zotero 当前选中项的能力。阶段 1 不增加 Zotero 伴侣插件，改用当前 Dock 搜索、多选和条目链接完成选择，不把“读取当前选中项”列为已实现功能。

### 思源引用数据模型

- 正文使用带稳定 itemKey 的 Markdown/Zotero 链接，多文献链接使用明确的 key 列表参数。
- 文档属性保存引用顺序、样式和快照；参考文献块使用独立自定义属性标识。
- 正文可见文本可随样式刷新，用户正文其他部分保持不动。
- 支持常见页码定位、叙述式/括号式和相邻文献合并；复杂 CSL 前缀/后缀规则不作为首阶段承诺。
- 更新参考文献时按块 ID/属性定位，不依赖脆弱的纯文本标题。

### 导出边界

阶段 1 的 Markdown、Word 和 LaTeX 导出以静态、正确排版的正文引用与参考文献为目标，不制作可在 Word/Zotero 中继续编辑的活域。未来若确有活域需求，单独立项评估。

### 标注导入边界

标注默认写入对应论文的 `Note` 下独立“PDF 标注”区域，不改写其他笔记。优先支持文本高亮、批注、页码和跳转链接；图片、墨水等复杂标注在取得真实样本后单独验证。
