# Zotero 笔记交互恢复与分层设计

## 背景与目标

用户在日常使用中遇到四类问题：Note 删除后无法恢复、功能过度集中于顶栏右键、设置项单页堆叠、窄窗口和对话框布局混乱。目标是在不改变现有 Zotero/文档数据模型的前提下，提供可恢复的绑定、符合思源习惯的命令入口，以及可扫描、可响应的设置和对话框。

选择方案 A：分层工作流与可恢复绑定。方案 B 只能暂时缓解高频问题，方案 C 会在本次引入过多引用编辑与批量任务改造，回归风险更高。

## 参考结论

- `reference/siyuan-plugin-zotero-cite/index.js` 使用 `this.protyleSlash` 注册 `/zotero`，并保留命令面板、顶栏与文档上下文入口；斜杠回调不覆盖无效 protyle。
- 同插件的对话框使用说明条、卡片列表、固定底栏；设置控件按行排列，避免固定双列挤压。
- `reference/siyuan-paper-manager/index.css` 使用设置 tabs、显式面板状态、容器查询、滚动内容区和固定操作区；窄屏切换单列。
- `reference/siyuan-paper-manager` 的文档菜单只显示与文档类型匹配的操作；顶栏用于全局命令，文档菜单用于当前文档。
- `reference/siyuan-plugin-citation/README_zh_CN.md` 将斜杠插入、命令面板、文档标题菜单和引用链接菜单区分为不同工作流。

只借鉴公开交互模式，不复制无许可证或非商用代码，不引入 ZBridge、Better BibTeX、debug-bridge 或新的运行时依赖。

## 非目标与约束

- 不复刻参考插件的 CSL 编辑、Zotero 当前选中项读取、批量任务中心或数据库业务。
- 不自动删除或覆盖 Note、论文页、Zotero 子笔记及用户现有文档。
- 不自动重建整棵文档树；恢复必须让用户知道将创建什么、绑定什么。
- 保持免构建 CommonJS、现有 Local API、锁、生命周期和多窗口修复。
- 完成后提交并推送 Git，但不创建 Release；版本号是否变化不改变这一限制。

## Note 与论文页恢复

### 绑定核验

`createOrOpenExclusive` 不再把“绑定字段齐全”视为文档存在。依次核验 parentDocId 与 noteDocId，使用内核块属性查询或等价的轻量存在性检查，并把错误区分为“不存在”和“查询失败”。查询失败不得被当成可重建，避免重复文档。

状态处理：

1. 两者都存在：保留现有行为，打开论文页。
2. 论文页存在、Note 缺失：进入 Note 恢复对话框。
3. 论文页缺失：提示论文页丢失；允许用户明确选择“重建论文页和 Note”。若路径下已有同名文档，不覆盖，先尝试认领并展示其身份。
4. 论文页存在、Note 字段为空：按原路径查找已有 Note；找到则重新绑定，找不到则进入恢复对话框。
5. Note 存在但绑定字段丢失：按论文页路径下的 `Note` 重新绑定，不新建。
6. 绑定所在 serverID 与当前 Zotero 不一致：按现有数据库换库规则处理，不在本次扩展自动认领。

### 恢复对话框

论文页存在时展示：论文标题、缺失对象、将使用的路径，以及以下操作：

- **重建 Note（主操作）**：创建新的 Note 子文档并写入初始模板，更新绑定；原 Zotero 子笔记保留，不回写、不删除。
- **重新绑定现有 Note**：仅在路径下已有未绑定 Note 时显示；确认后复用其 ID 和内容。
- **打开论文页**：关闭对话框并打开现存论文页，不改变绑定。
- **取消**：不写入任何数据。

论文页缺失时主操作改为“重建论文页和 Note”，明确提示原论文页元数据可以重建，但已删除的正文和 Note 内容无法由插件恢复。只有 Zotero 子笔记仍在时才提示可通过后续同步找回内容；本次不自动下载或覆盖。

恢复成功后打开目标 Note；失败时保留当前绑定，只有完整成功后才保存新绑定。恢复流程复用同一文献锁和绑定锁，避免多窗口重复创建。

Dock 条目在检测到 Note 缺失时提供“恢复 Note”操作，而不是继续显示无效的“打开笔记”。其他刷新、回传和翻译操作在恢复前禁用，并解释原因。

## 命令入口与信息架构

### 斜杠命令

注册 `this.protyleSlash`，支持以下独立入口：

- `/zotero`：打开现有多选引用选择器。
- `/znote`：打开文献搜索并创建/打开所选论文 Note。
- `/zexport`：打开现有导出对话框。

每个条目使用中英文可检索 filter，并复用现有方法。回调只在 rootID 有效时更新当前 protyle，不清理已由思源删除的触发文本。无有效编辑器时给出明确提示，不产生写入。

### 命令面板与顶栏

保留现有插入引用、导出命令，增加：打开 Zotero 文库、创建/打开 Note、统一多页引用、导入文献、环境/连接检查。异步回调统一经过错误捕获，避免静默失败。

顶栏左键改为打开主工作菜单，不再直接跳设置。菜单按“文库与笔记、引用与写作、导入与工具、设置”分组；右键菜单可保留为快捷入口，但不作为唯一入口。

### 文档上下文菜单

通过 `open-menu-content`、`click-editortitleicon`、`open-menu-doctree` 添加与文档类型匹配的操作：

- 普通文档：插入引用、导出文档、统一多页引用。
- 论文页：打开/恢复 Note、刷新元数据、回传 Note、导入标注、翻译。
- Note：打开论文页、刷新元数据、回传 Note、导入标注、翻译。
- 非论文相关文档不显示论文专用操作。

菜单处理器保存后卸载时按函数身份解绑，文档 ID 只从当前事件读取，不依赖激活编辑器。菜单异常不能阻断思源原菜单。

## 设置页重构

使用单一设置容器和 tabs，避免连续堆叠：

1. **基础**：笔记本、根文档、作者显示数量、Zotero 连接测试。
2. **同步**：启动导入、文库同步方式与间隔、Note 自动回传、Kimi 工作队列。
3. **写作**：引用样式、引用形式、Note 初始模板、多文档说明。
4. **翻译**：pdf2zh 路径、源/目标语言、任务并发、每篇请求并发、密钥名称及密钥设置入口。
5. **高级**：数据与恢复说明、绑定检查入口、调试/支持信息；不放普通高频选项。

设置使用明确 `role=tablist/tab/tabpanel`、选中状态和键盘可操作按钮。每个面板独立滚动，底部保存/取消操作固定。保存仍复用统一规范化与 `saveData`，切换 tab 不触发保存或重置草稿。

每篇请求并发数补全设置控件；密钥区域只显示名称，不显示值。打开密钥和变量设置失败时给出手动路径提示。

## 对话框与 Dock 响应式规则

- 使用 `width: min(…, calc(100vw - 24px))` 与 `max-height: calc(100dvh - 64px)`。
- 内容区滚动、操作区固定；长标题和路径允许换行或省略，不能把按钮挤出窗口。
- 引用选择、导出、导入、翻译、回传预览统一说明区/内容区/底栏结构。
- 宽屏字段可采用两列，容器宽度不足时单列，不依赖整个思源窗口宽度的假设。
- Dock 操作默认只显示主要动作，次要动作进入条目菜单；窄 Dock 使用图标+可访问名称，避免一排按钮全部截断。
- 保留键盘焦点、禁用原因、错误提示与主题变量，支持明暗主题。

## 测试与验收

- 绑定状态矩阵：完整、Note 缺失、论文页缺失、字段为空、查询失败、已有 Note 可认领、多窗口并发。
- 恢复安全：取消不写、重建不改 Zotero、认领保留内容、失败不保存半成品绑定。
- 斜杠 filter 与回调、无效 protyle、命令异常、上下文文档类型和事件解绑。
- 设置 tabs、草稿保留、所有设置项可访问、保存后规范化不变。
- 响应式 DOM/CSS 静态检查及真实思源宽/窄窗口验证；所有现有测试继续通过。
- 真实场景：备份后删除测试 Note，完成重建和重新绑定；删除测试论文页后确认重建；取消流程无写入。
- 最终独立代码审查、完整测试、真实交互验证后提交并推送，不发布 package Release。

## 实现者可决定的事项

- 使用现有 DOM 工具函数还是补充少量可复用的小组件事先取决于当前代码一致性，但不引入框架。
- 具体 tabs 文案、图标与菜单顺序可随思源原生风格微调。
- 轻量文档存在性检查可根据内核 API 选择最快且能区分“查询失败”的方式。

## 可行性检查后的确定规则

- **同名论文页认领（用户选择）**：只在精确预期路径下，且文档没有 Zotero 绑定或其绑定明确匹配当前文献时提供“绑定到此文档”。对话框展示标题、路径和现有绑定；必须经用户确认。绑定属于其他文献时绝不换绑，使用 itemKey 后缀新建。普通同名文档不会被静默覆盖。
- **Note 认领**：只检查论文页下精确路径 `Note`，不搜索或自动选择 `Note 2` 等候选。该 Note 不得已被其他绑定引用；若含文献属性，则必须与当前文献匹配。重新绑定保留 Note 和论文页正文，不执行元数据重写；用户可随后主动刷新元数据。
- **单选文献搜索**：新增轻量的 `openNotePicker`，与 Dock 搜索共享过滤逻辑，供 `/znote` 和命令面板使用；不复用多选引用选择器。
- **命令语义**：“打开 Zotero 文库”表示展开并聚焦插件 Dock，不启动外部应用；“检查连接”复用 Zotero 连接探测并显示结果，不扩展成新的环境管理器。
- **高级绑定检查**：显示缺失/异常绑定列表，并允许逐条进入上述恢复流程；没有异常时不显示多余操作。
- **Dock 检测时机**：采用点击时核验，避免每次渲染为所有绑定发起 N 个内核请求。发现缺失后更新该条目的状态与恢复入口，不在后台批量探测。
- **恢复写入边界**：恢复与认领不重写现存 Note 或论文页内容；只有新建 Note 使用初始模板，只有新建论文页生成元数据。Zotero 子笔记在恢复过程中不修改。
